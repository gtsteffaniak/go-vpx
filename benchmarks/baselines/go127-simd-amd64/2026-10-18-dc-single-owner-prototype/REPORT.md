# Private x64 paired-DC review

Review PASS for correctness and safety; no native or emulated performance claim. Only four Go paths differ from frozen final ARM50: new AMD native/inplace owners, new AMD coefficient test, and the complementary generic-other build tag. All ARM source and existing AddConstantPair4 bytes are unchanged. ROOT and the prototype source were not edited.

SIMD int32 Add4 wraps before arithmetic shift3 exactly as the original public delta conversion. The rounded range is [-268435456,268435455], so negating it cannot overflow int32. Positive and negative corrections are independently clamped 0..255; exactly one is nonzero. For any input byte, saturated add of the positive part then saturated subtract of the negative part equals final clipping of pixel+roundedDelta. The VPSHUFB indices select the low byte of lanes 0/1 and repeat four copies of each coefficient in both eight-byte rows. The saved independent int64 oracle exercises 327,680 coefficient pairs, all 16 lanes.

Fast guards prove full four-row eight-byte windows before unsafe loads/stores: strides >= 8 and stride<=(len-8)/3 avoid multiplication overflow, and both row packets stay within checked windows. No capacity or padding is consumed. Exact alias with equal pitches has independent rows; disjoint visible spans preclude any source/destination write dependency. Only those domains preload two rows before two ordered exact 8B stores. Partial overlap, zero/negative/huge strides and short buffers retain the original block0-then-block1 enabled path and destination-slice-before-four-byte-read order. Disabled fallback retains the original DSP scalar row checks/per-pixel dependencies. Nil and malformed windows preserve panic/partial backing behavior in the tested domains.

External Go-overlay tests compare candidate public and direct-owner paths with a frozen copy of the actual parent public body, fixing its formerly false AMD native constant to false. This preserves the old AddConstantPair4 dispatcher as the denominator; all its dependencies are byte-identical. The generic lattice covers 156,000 checks and inplace 55,296 per mode, including partial/overlap/full backing, clipped/spare capacity, unaligned windows, extreme coefficients/strides, panics and partial writes. Native-selected Rosetta checkptr=2 and race+checkptr=2 pass, including artificial Enabled=false. Actual AVX/AVX2-disabled runs pass disabled tests and correctly skip native-only tests. Cross-race compilation with clang -arch x86_64 succeeded. These are correctness checks only.

Actual optimized Darwin AMD64 DSP/decoder binaries show generic 297 and inplace 192 total owner instructions, with no YMM, ZMM or mask-register instructions. All XMM instructions in both full owners are VEX, no vector stack accesses; coefficient and row helpers inline, valid fast paths have no calls. Thus no AVX512 API or return fence for newly dirtied YMM state is required; Enabled is checked before the first vector instruction. Cold paths still call scalar fallback/panic/morestack and are not described as leaf functions. All five actual decoder bodies retain a call through the public inplace wrapper. Frames reserve 128 bytes generic and 88 bytes inplace; these ABI costs are real and native CI must decide performance.

The initial unsupported ARM narrowing-API compile attempt and failed source are preserved, alongside final root validation and independent commands/logs. No thresholds were weakened and no assembly, dependency or toolchain patch was added.
