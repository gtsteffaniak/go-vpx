## Contract proof

The specialization requires Enabled plus the actual AVX2 feature, and complete pairwise disjoint touched spans for coeff/iscan/q/dq/classes (optional outputs omitted). Overlap uses ordered uintptr differences; no end-pointer addition, out-of-object pointer formation, or uintptr-to-pointer dereference. It conservatively declines read-only aliases as well. n bounds prove all 32-byte vector accesses and the two exact 8-byte class stores. Pointer origins remain typed Go slice pointers through unsafe.Add. Guard and public validation run before any output store or YMM operation.

Unsigned abs(-32768)=32768 plus round<=32767 fits uint16 exactly (max 65535), then clamps 32767. Signed high multiplication with nonnegative quant<=32767 yields magnitude <= 16383. XOR/sub sign restoration, low16 dequant multiplication and the existing LUT match scalar wrapping/classes. Signed scan max starts atzero, preserving EOB behavior including nonpositive scan values. Only disjoint windows change packet store order. Every other path retains the original 8-lane order and exact public panic order. Direct AVX cleanup follows the GPR result reduction. Valid fast paths cannot encounter a Go bounds panic after entering YMM work; fabricated invalid slice pointers remain outside the Go slice contract.

## Generated-code evidence and unresolved cost

Linux wide YMM-live regions contain 140 instructions total, with a 48-instruction AC loop, no calls, legacy vector instructions or vector stack operations. Both Linux and Darwin show direct VZEROUPPER after the GPR EOB reduction. The function frame is 168 bytes, equal to the base 8-lane function. The no-classes LUT-zero MOVUPS is before the first YMM instruction; legacy ops elsewhere belong to the mutually exclusive original 8-lane fallback. The overlap helper's zeroing also runs before any YMM operation.

The unchanged overlap algorithm remains one ordinary pre-YMM helper call, argument setup/restoration and up to 10 pairwise comparisons. The first packet builds mixed DC/AC vectors before the steady AC-only loop. This setup can erase a gain  at n64; native CI must decide. n16 does not evaluate feature/overlap checks, but its placement/register allocation is not claimed instruction-identical; keep the strong public n16 controls. `initial-class-bounds/` preserves the first production variant and LLVM output, where checked class slices retained unnecessary bounds/address branches. The final two 8-byte stores remove those branches without changing class packing.
